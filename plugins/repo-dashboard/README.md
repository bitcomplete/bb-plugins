# Repo Dashboard

Repo Dashboard adds a BB sidebar view of weekly GitHub pull request activity for the `parsleyhealth`, `bitcomplete`, and `ira-cscc` organizations. The **Cscc** tab uses `ira-cscc`. Select an organization and a Monday–Sunday week in Eastern Time (ET). Week boundaries and daily bars adjust for daylight saving time. The daily chart shows organization activity; each contributor row shows its own seven-day pattern. Hover over or focus a day to compare it across contributors. Select a day to show only its contributor and repository event details; the counts, Flow scores, and bars remain weekly. Select the day again or use **Clear day** to return to all details. Expand a contributor to see counts by repository, then expand a repository to inspect linked PRs.

The dashboard counts PRs opened, PRs merged, distinct PRs reviewed, and PRs closed without merging. **In progress** counts PRs created within the 90 days before the snapshot that remain open at the end of the selected week, including drafts and PRs opened earlier. For the current week, it counts PRs open when the dashboard fetches data. In progress is a snapshot, so it does not add to daily bars or activity totals. The age strip shows this snapshot on a 0–90 day axis, with guides at 7 and 30 days. Expand it to inspect age ranges, then expand a repository to inspect its PRs. The **90-day in-progress trend** shows the current total, its absolute change from the previous week, and the percentage change in a tooltip. A zero previous total has no percentage baseline. Because each snapshot uses a rolling 90-day window, a decrease can reflect PRs aging out. Each contributor gets one reviewed count per PR per week, even after multiple submitted reviews; its day mark uses the latest submitted review that week. Two contributors who review the same PR each get one count. Reviews on PRs opened before the week count when the review falls inside the selected week. Bot accounts and pending reviews do not count.

The **Flow** column combines weekly activity with the change in in-progress PRs: opened + 2 × merged + 0.5 × distinct PRs reviewed − 0.25 × any increase in in-progress PRs since the previous week. The score has one decimal place. A carried-over backlog does not increase the score, and a shrinking backlog does not add a bonus because merges already count. The column shows a dash until the previous snapshot loads or when that snapshot is unavailable. Use the raw counts alongside the score; it measures this mix of activity, not contributor productivity.

The week note reports the busiest day and the in-progress change when the previous snapshot is available. It labels current-week activity as partial and reports an empty week without inventing a peak.

Expand **Review connections** to see the distinct PRs that each reviewer reviewed for each PR author and the share of reviewed PR contributions with author data. Older cached activity can lack that metadata; use **Refresh** to fill it.

**Week postcard** starts expanded with space above it. It previews and downloads a local SVG with weekly counts, average daily Flow per active contributor, a daily stem chart, and labels for current-week activity and the 90-day snapshot. The average uses contributors with at least one PR activity event in that week, including closed PRs, and applies each contributor's Flow score before averaging. Contributors with only in-progress PRs do not enter the average. The postcard shows each week's active contributor count. It divides the selected average by elapsed Eastern Time calendar days for the current week or seven days for a completed week. It divides the full prior week's average by seven days. For the current week, the separate opens, merges, and distinct contributor–PR review rows still compare activity through the saved fetch time with the same Eastern Time weekday and time in the previous week. The Flow rate compares against the full prior week, so its comparison uses a different period from those count rows. The Flow rate uses the selected, previous, and two-weeks-ago in-progress snapshots. If the earliest snapshot is not saved, select **Load Flow baseline** to fetch it. The in-progress change compares snapshots, including the previous week's end; it does not reconstruct a same-point backlog. The postcard checks saved prior-week activity and the Flow baseline without a GitHub request. If prior activity is missing, select **Load previous week** to fetch it. If older cached reviews cannot establish the prior count at the cutoff, the review comparison shows as unavailable; select **Refresh previous week** to update the cache. **Review connections** starts collapsed. Both sections stay scoped to the selected week when you select a day.

The plugin reads GitHub through the primary host's authenticated `gh api graphql` command. Run `gh auth login` on that host with access to all three organizations. The plugin does not write to GitHub. It loads the previous in-progress snapshot after the selected week's activity appears, without rerunning the previous week's activity searches. It stores successful activity and snapshot results across plugin reloads. Current-week results expire after 24 hours or at the end of the Eastern Time week, whichever comes first. Completed-week results expire after 30 days. Select **Refresh** to fetch fresh data and update the caches. A failed refresh preserves the last successful result. GitHub search caps each query at 1,000 PRs, and this plugin reports an error instead of displaying partial totals when a query or a PR's review history exceeds the data it can retrieve.

Historical in-progress counts use current open PRs and PRs that closed after the selected week. GitHub search does not expose earlier open and close transitions in these results. If a PR closes and reopens, its historical in-progress status can be inaccurate.
