# When the loop needs attention

Start with `bb self-improve doctor` and `bb self-improve status` in the intended BB instance. A failed or waiting run lists what to check next to its recorded codes. A quiet ledger can mean no eligible evidence, a deferred prerequisite or a failed run.

| What you see | What to check |
| --- | --- |
| **No problems recorded** | Inspect mining coverage, or add an owner problem/goal. A fresh ledger is empty. |
| **Learning paused** | Scheduled enqueueing is off. Explicit manual requests can still run. |
| Provider/model missing | Configure the worker project/environment, then use the dashboard's **Execution** pickers. |
| Authentication failure | Use the selected provider's supported BB sign-in/routing diagnostics. There is no Self improve model API-key pool to repair. |
| Worker environment missing | Supply real BB project/environment IDs. A directory string alone is not a registered environment. |
| Unknown native costs not authorized | `budgets.allowUnknown` is set to `false`, which pauses agent work. Remove it or set it to `true`; see [costs](costs.md). |
| Budget/admission refused | Inspect shared native/chat/detector observations, unknown reports and reservations before raising limits. |
| Configuration changed while editing | Reload **Execution** settings before saving; do not overwrite newer settings with a stale selection. |
| Chat became inactive | Reopen it from the ledger after privacy/execution changes. Old history is retained; old tool authorization is not reused. |
| Native reconciliation pending | BB thread/event access or cleanup needs recovery. Preserve the stored identity; do not create duplicate tasks to hide an uncertain dispatch. |
| Terminal task history unavailable | Configure a trusted [structured task-outcome producer](task-outcomes.md). A thread error is not authoritative task history. |
| Awaiting research snapshot | Finish problem ranking, scout and inventor against the same snapshot before ranking solutions. |
| Paper credibility pending | Required source evidence is missing; unknown citation measures do not satisfy a gate. |
| No eligible solution | Read assessment reasons, dependencies and prior attempts. |
| A fix passed but isn't applied | **Apply tested improvements automatically** is off (approve it under Improvements), the fix was disabled, or the per-turn limit is full (it shows as waiting). |
| Solution marked **From an earlier version · not applied** | Its record comes from an earlier version of Self improve. It is kept for history and is not added to turns. |

## Recover without losing attribution

BB owns supported provider retries and account failover. Self improve retains native task/thread identities and reported usage. A timeout or lost spawn acknowledgement does not prove no work ran. Reconciliation should recover that identity before another attempt is authorized.

Optional Laya failure should not disable periodic mining. Diagnose the detector separately; enabling it does not make its infrastructure free.

Current fixture tests do not establish that Claude Code, Codex, every host version, or every configuration works end to end. The delivered preview needs its own installation and real-provider evidence.

## Share a useful report

Include the revision, BB version, stage/job or solution ID, redacted diagnostic code, expected behavior and whether it reproduces in scratch. Keep credentials, private transcripts and sealed evaluation cases out. Generalized descriptions and evidence pointers are usually enough to start.
